# Resident backend implementation

This documents the implemented backend at 2026-09-26. Complete layer-0 decoder
inference and complete 24-layer two-token inference have passed physical CS3
validation, including actual-input operator qualification and full weight retention.
Current evidence and active attempt are tracked in ../STATUS.md. The executable
placement is defined in `core/resident_geometry.py` and generated by
`tools/build_full_layout.py`; the older 26-column capacity plan is historical.

## Model and residency

The full original `openai/gpt-oss-20b` checkpoint remains resident: all 24 layers,
all 32 experts per layer, top4 routing, untied embedding/head, original biases,
norm gains and learned attention sinks. Expert blocks remain MXFP4, including
all original E8M0 scales; other parameters remain BF16. There is no host expert
execution, weight pruning, or per-token/per-layer parameter reload.

The first runtime allocates 96 positions per KV head. Every required causal
position is retained for positions 0..95, including the window-128 layers.
Requests beyond capacity are rejected. Each of the eight KV-head workers per
layer holds 6144 BF16 K values and 6144 BF16 V values (24 KiB total). Extending
context requires a separately validated distributed cache/attention design.

fabric at offset (4,1), one SDK memcpy channel.

| Layer L | x=46+27L .. 72+27L | Attention, router, all 32 experts, join and KV |
| Vocabulary head | x=694..735, y=0..1139 | Complete untied 201088 x 2880 projection |

Each layer occupies 27 columns:

|---|---|
| 0 | 38 QKV row tiles; layer 0 also returns embedding slices |
| 1 | Two more QKV tiles, all O projection and router |
| 2 | Attention controller and explicit prefix collectors |
| 3 | Eight KV workers at y=0..7; MoE controller at y=1159 |
| 4..13 | 36 gate/up chains per expert, ten MXFP4 contraction PEs each |
| 14 | Gate collection, original SwiGLU, down-input broadcast |

Expert e has rows 36e..36e+35. Every MXFP4 tile is 160 x 288, occupying 23,040
packed value bytes and 1440 original scale bytes. BF16 projection tiles are
128 x 96, stored column-major for the accepted kernel. QKV uses 30 contraction
PEs per tile, O uses 43 with exactly 32 zero-padded input elements, and router
uses 30 PEs with 32 valid output rows. Bias lives at the last contraction PE.

Embedding/head have 38 complete vertical chains of 30 PEs per column. The
1571 vocabulary row tiles occupy 42 columns; padded rows in the last column
still relay replies. The loader covers all 459 original tensors in bounded
transfers of at most 1 MiB. Passing its packing audit is not evidence that a
full-model hardware upload has completed.

## Fixed control and on-wafer dataflow

After one initialization, neural H2D consists of one token ID at the west.
The host executes 1990 fixed commands with only phase/layer/index arguments;
it does not compute neural intermediates or select experts. All hidden states,
KV, routing and expert outputs remain on wafer. Host diagnostic reads happen
only after a complete token and are never forwarded into computation.

| Phase | Count per token | Work |
|---|---:|---|
| 1 | 1 | West token, epoch, embedding metadata |
| 2 | 30 | Gather 30 original 96-element embedding slices |
| 3 | 24 | Layer input RMSNorm and all QKV projections |
| 4 | 24 x 40 | Gather QKV row tiles |
| 5 | 24 | Original YaRN RoPE for Q and K |
| 6 | 24 x 8 | Append K/V, GQA with learned sinks, collect output |
| 7 | 24 | O projection |
| 8 | 24 x 23 | Gather O output tiles |
| 9 | 24 | Attention residual and direct delivery to MoE |
| 10 | 24 | MoE RMSNorm, full router, top4 and selected softmax |
| 11 | 24 | Expert IDs, probabilities and selection mask |
| 12 | 24 | Selected packed expert GEMVs, SwiGLU, down outputs |
| 13 | 24 | Four results in router-rank order, weighted join/residual |
| 14 | 24 | Layer-to-layer or last-layer-to-head handoff |
| 15 | 1 | Final RMSNorm and complete vocabulary projection |
| 16 | 38 | Distributed vocabulary argmax and east token output |

This is the functional bring-up schedule, not an optimized throughput claim.
The same physical runtime and parameter/KV allocations survive successive
calls. The host feeds the actual sampled token back at the west.

### Same-command handoffs

Both sender and receiver must participate in the producing command. A sender
blocked on a receiver that waits for the next host command can prevent that
next command from reaching the receiver.

- Attention phase 9 sends its residual output while the MoE controller receives
  in phase 9. MoE phase 10 uses the saved `hidden_ready` buffer.
- Join phase 14(L) sends while attention controller L+1 receives in that same
  phase, before its usual layer-identity filter. Its own phase 3 normalizes.
- Join phase 14(23) sends while the head controller receives. Phase 15 performs
  final normalization and vocabulary projection.
- Phase 16 index 37 sends the final candidate while the east endpoint receives.

Receive/TX descriptors have finite lengths; buffers remain leased until their
completion callback. Explicit alternating-color relays avoid merging two RX
directions into one color, which WSE-3 disallows.

## Numerical semantics

RMSNorm uses compensated FP32 square summation, direct gamma and epsilon 1e-5.
The compensated version passed 144 real-input physical accuracy cases, all
within one BF16 ULP of a directly rounded FP64 reference. Attention preserves original Q64 /
KV8 / head64 grouping, split-half YaRN, concentration, and learned sinks as an
extra denominator logit. Frequencies are initialization constants; per-token
rotations and attention execute in CSL. The initial two-position validation is
not a long-context trigonometry accuracy claim.

MXFP4 decoding uses low nibble first and the original E8M0 block scale. Expert
gate/up channels are interleaved. Gate is upper-clamped to 7, up to [-7,7], and
activation is gate * sigmoid(1.702 * gate) * (up + 1). Original BF16 rounding
boundaries distinguish expert matmul/bias from attention/router linear bias.
All experts receive finite metadata/input traffic; only selected experts run
their arithmetic. Global collection follows router rank, preserving weighted
sum order. Exact router-logit ties use lower expert ID; the Torch backend may
choose a different order for exact ties.
PyTorch explicitly does not guarantee stable indices for tied `topk` values;
see its [official topk documentation](https://docs.pytorch.org/docs/2.14/generated/torch.topk.html).
This does not excuse a wrong non-tied selection: qualification checks the complete
32-logit vector and deterministic descending-score/lower-ID order independently.

Head candidates are taken after the original BF16 output rounding. Forty-two
horizontal columns reduce to one candidate for each of 38 row groups; explicit
northbound collectors deliver those 38 candidates to the head controller.
Exact logit ties use lower token ID. All 201088 vocabulary entries participate.

## Physical admission and acceptance

Representative edge roles and the complete decoder have compiled and passed
actual ELF SRAM checks; attention/MoE/decoder have physical acceptance receipts.
A full-fabric attempt must independently pass every actual ELF's SRAM gate,
embedded-source hashes and artifact hash before allocating an inference device.
The 4096-byte stack allowance is a declared bound, not a measured stack peak.

The initial complete-model run uses two real autoregressive `Hello` steps and
retains strict comparisons for every saved attention/MoE state and ordered
expert IDs. Separate actual-input operator checks account for BF16 accumulation
and exact routing ties, under `NUMERICAL-QUALIFICATION.md`. Exact generated IDs,
all active PE epochs, persistent KV progression and exhaustive unchanged weights
remain mandatory. Failures preserve actual states and job/resource audits.
Full-model acceptance requires numerical qualification, normal stop and release.
